### 1. Цели и предпосылки

#### 1.1. Зачем идем в разработку продукта?

**Бизнес-цель:**
Создать веб-сервис, позволяющий пользователям оценить стоимость квартиры в России по её параметрам на основании реальных данных рынка недвижимости 2021 года. Сервис ориентирован на покупателей, продавцов и аналитиков рынка недвижимости.

**Почему станет лучше от использования ML:**
Текущие аналоги (ЦИАН, Яндекс.Недвижимость) показывают только актуальные объявления. Наш сервис позволяет оценить историческую стоимость квартиры по параметрам, используя ML-модель, обученную на 11+ млн реальных объявлений. ML-модель учитывает нелинейные зависимости между признаками (площадь, расположение, тип здания), которые невозможно уловить простыми правилами.

**Что будем считать успехом итерации:**
- MVP доступен в интернете и работоспособен
- Модель превосходит baseline (медиана по группе) по метрике MAPE минимум на 15%
- Время ответа API < 500 мс
- Студенты и преподаватель могут воспользоваться сервисом на защите

#### 1.2. Бизнес-требования и ограничения

**Бизнес-требования:**
- Пользователь вводит параметры квартиры (регион, тип здания, кол-во комнат, площадь) и получает оценку цены
- Сервис показывает диапазон цен (confidence interval) и сравнение с похожими квартирами
- Система поддерживает дообучение на новых данных (демонстрация в чекпоинте 3)

**Бизнес-ограничения:**
- Бюджет: $0 (бесплатный хостинг - Streamlit Cloud)
- Данные только за 2021 год (статический датасет с Kaggle)
- RAM ограничение Streamlit Cloud: 1 GB
- Команда: 2 человека, учебный проект

**Что ожидаем от итерации (Чекпоинт 1):**
- Формализованная постановка задачи
- Проведенный EDA с выводами
- Заполненные Data Contracts
- Архитектурная диаграмма
- Список рисков с митигациями

**Описание бизнес-процесса пилота:**
1. Пользователь заходит на веб-страницу (Streamlit)
2. Заполняет форму: регион, тип здания, кол-во комнат, площадь, этаж (опционально)
3. Нажимает "Оценить стоимость"
4. Streamlit отправляет запрос к FastAPI сервису
5. FastAPI возвращает: предсказанную цену, диапазон, статистику похожих объектов
6. Streamlit отображает результат с визуализацией

**Критерии успешного пилота:**
- MAPE (Mean Absolute Percentage Error) <= 25% на тестовой выборке
- Uptime > 95% в течение недели
- Положительная обратная связь от студентов на защите

#### 1.3. Что входит в скоуп проекта/итерации, что не входит

**Входит в итерацию (Чекпоинт 1):**
- Загрузка и очистка данных
- EDA с визуализациями
- Data Contract для источника данных
- Архитектурная диаграмма системы
- Baseline-решение (медиана по группе)
- Данный ML System Design Doc
- Анализ рисков

**НЕ входит в итерацию:**
- Обучение ML-моделей (чекпоинт 2-3)
- Деплой приложения (чекпоинт 4)
- Мониторинг и алерты (чекпоинт 4)
- Real-time данные (только статический датасет 2021)

**Описание результата с точки зрения качества кода:**
- Код в Git-репозитории с README
- Jupyter notebooks с воспроизводимым EDA
- Документация в Markdown

**Технический долг:**
- Полный датасет (11 млн) может не влезть в RAM -> нужен семплинг или чанковая обработка
- Data Contract пока без автоматической валидации (добавим в чекпоинте 2)

#### 1.4. Предпосылки решения

- **Данные:** Используем полный датасет Russia Real Estate 2021 с Kaggle (~11.3 млн объявлений с 7 площадок)
- **Горизонт прогноза:** Статическая оценка (нет временного ряда, т.к. данные за один период)
- **Гранулярность модели:** Одна модель на всю Россию (с регионом как признаком). При необходимости - отдельные модели по федеральным округам
- **Целевая переменная:** Цена квартиры (price) в рублях
- **Тип задачи:** Регрессия
- **Ключевые признаки:** регион, тип объекта (вторичка/новостройка), тип здания, кол-во комнат, площадь, координаты

### 2. Методология

#### 2.1. Постановка задачи

**Тип задачи:** Регрессия - предсказание цены квартиры по её характеристикам.

**Формально:** Дано множество квартир X = {x_1, ..., x_n}, где x_i = (region, object_type, building_type, rooms, area, geo_lat, geo_lon, ...). Нужно построить функцию f: X -> R, минимизирующую MAPE на тестовой выборке.

**Объект применения:** Квартиры на российском рынке недвижимости (данные 2021 г.)

#### 2.2. Блок-схема решения

**Baseline:**
```
Kaggle CSV --> Очистка данных --> Группировка (регион + комнаты + тип) --> Медиана по группе --> Предсказание
```

**MVP (основной):**
```
Kaggle CSV --> Очистка данных --> Feature Engineering --> Train/Val/Test split
                                                              |
                                        [Train] --> Обучение моделей (LinearReg, CatBoost)
                                                              |
                                        [Val] --> Подбор гиперпараметров
                                                              |
                                        [Test] --> Финальная оценка
                                                              |
                                        Сохранение лучшей модели (.joblib)
                                                              |
                                        FastAPI сервис (/predict)
                                                              |
                                        Streamlit UI
```

#### 2.3. Этапы решения задачи

**Этап 1 - Подготовка данных (Чекпоинт 1-2)**

| Название данных | Источник | Ресурс для получения | Качество проверено |
|----------------|----------|---------------------|-------------------|
| Russia Real Estate 2021 | Kaggle (mrdaniilak) | DS - загрузка через API | Нет (EDA в процессе) |

Целевая переменная:

| Переменная | Описание | Тип | Диапазон |
|-----------|----------|-----|----------|
| price | Цена квартиры в рублях | float | > 0, ожидаемо 500K - 100M |

Признаки:

| Признак | Описание | Тип | Обработка |
|---------|----------|-----|-----------|
| region | Код региона РФ | categorical (int) | Label/Target encoding |
| object_type | 0=вторичка, 2=новостройка | categorical | One-hot |
| building_type | Тип здания (0-6) | categorical | One-hot |
| rooms | Кол-во комнат (-1=студия) | int | As-is, -1 -> 0 |
| area | Площадь (м2) | float | Log-transform |
| geo_lat | Широта | float | As-is или кластеризация |
| geo_lon | Долгота | float | As-is или кластеризация |

Результат этапа: Очищенный датасет в формате Parquet, train/val/test split, feature matrix.

**Этап 2 - Построение моделей (Чекпоинт 3)**

*Baseline:*
- Медиана цены по группе (регион + кол-во комнат + тип здания)
- Ожидаемый MAPE: ~40-50%

*MVP - Модель 1: Ridge Regression*
- Линейная модель на подготовленных признаках
- Ожидаемый MAPE: ~30-35%

*MVP - Модель 2: CatBoost Regressor*
- Градиентный бустинг с нативной поддержкой категориальных признаков
- Ожидаемый MAPE: ~15-25%

**Формирование выборки:**
- Train: 80% данных (случайная стратифицированная выборка по регионам)
- Validation: 10%
- Test: 10% (заморожен, используется только для финальной оценки)
- Retrain set: отдельный 10% сплит для демонстрации дообучения

**Метрики качества:**
- **MAPE** (Mean Absolute Percentage Error) - основная, связана с бизнесом: "на сколько % мы ошибаемся в цене"
- **MAE** (Mean Absolute Error) - вспомогательная, в рублях
- **R2** - вспомогательная, доля объясненной дисперсии

Целевые метрики: MAPE <= 25% для > 70% регионов.

**Риски этапа:**
- Для редких регионов (малое кол-во данных) модель может быть неточной
- Выбросы в ценах (ошибки ввода) могут сильно влиять на MAE
- Log-трансформация цены может улучшить метрики, но усложнить интерпретацию

**Этап 3 - Дообучение (Чекпоинт 3)**

- Триггеры: data drift (KS-test на распределении цен), падение MAPE > 5%
- Стратегия: инкрементальное дообучение CatBoost (warm start)
- Демонстрация: обучаем на 80%, показываем drift на 10% "новых" данных, дообучаем

**Этап 4 - Деплой и мониторинг (Чекпоинт 4)**

- FastAPI сервис с эндпоинтами /predict, /health, /retrain
- Streamlit UI на Streamlit Cloud
- Мониторинг через Evidently AI (data drift, model drift)
- Алерты при деградации метрик

### 3. Подготовка пилота

#### 3.1. Способ оценки пилота

Пилот оценивается на защите проекта:
- Демонстрация работающего веб-приложения
- Студенты и преподаватель вводят параметры квартир и получают оценки
- Сравнение с реальными ценами из открытых источников

#### 3.2. Что считаем успешным пилотом

- MAPE <= 25% на тестовой выборке
- Приложение доступно по URL и работает без сбоев во время защиты
- Система корректно обрабатывает граничные случаи (студия, неизвестный регион)
- Демонстрация дообучения показывает улучшение метрик

#### 3.3. Подготовка пилота

- Streamlit Cloud: бесплатный тариф (1 GB RAM, 1 CPU)
- Для укладывания в лимиты: семплирование данных до ~1-2 млн записей или предагрегация
- Модель сохраняется в .joblib (~10-50 MB), загружается в память при старте
- FastAPI может быть развернут на том же сервере или отдельно (Railway/Render бесплатный тариф)

### 4. Внедрение

#### 4.1. Архитектура решения

```
[Пользователь] --> [Streamlit Cloud]
                        |
                   HTTP запросы
                        |
                   [FastAPI Service] <-- ML модель (.joblib)
                        |
                   [Parquet/SQLite] <-- Данные для статистики
```

**API методы:**
- `POST /predict` - принимает параметры квартиры, возвращает предсказанную цену и confidence interval
- `GET /health` - healthcheck
- `POST /retrain` - запуск дообучения модели (чекпоинт 3)
- `GET /stats` - статистика по региону (медиана, квартили)

#### 4.2. Описание инфраструктуры и масштабируемости

**Выбор:** Streamlit Cloud (UI) + Railway/Render (FastAPI)

**Плюсы:**
- Бесплатно
- Автоматический деплой из GitHub
- Достаточно для учебного проекта

**Минусы:**
- Ограничения по RAM (1 GB)
- Cold start при неактивности
- Нет гарантий SLA

**Почему лучше альтернатив:**
- Docker + VPS: требует оплаты и настройки
- Heroku: бесплатный тариф отменен
- GCP/AWS: overproduce для учебного проекта

#### 4.3. Требования к работе системы

- **SLA:** 95% uptime (учебный проект)
- **Задержка:** < 500 мс для /predict
- **Пропускная способность:** < 10 RPS (достаточно для демо)

#### 4.4. Безопасность системы

- Нет аутентификации (публичный демо-сервис)
- Rate limiting для защиты от злоупотреблений
- Валидация входных данных (диапазоны, типы)

#### 4.5. Безопасность данных

- Датасет публичный (Public Domain на Kaggle)
- Нет персональных данных (адреса анонимизированы через FIAS ID)
- Нет нарушений GDPR

#### 4.6. Издержки

- $0/месяц (бесплатные тарифы Streamlit Cloud + Railway/Render)
- При необходимости масштабирования: ~$5-10/месяц за VPS

#### 4.7. Integration points

- Streamlit UI --> FastAPI: HTTP REST (JSON)
- FastAPI --> Model: joblib.load() при старте, predict() при запросе
- FastAPI --> Data: pandas read_parquet для статистики
- GitHub --> Streamlit Cloud: автодеплой при push в main

#### 4.8. Риски

| # | Риск | Категория | Причина | Последствие | Митигация |
|---|------|-----------|---------|-------------|-----------|
| 1 | Грязные данные (дубликаты, выбросы цен) | Данные | Парсинг с множества сайтов без единого стандарта | Модель учится на шуме, неадекватные предсказания | Дедупликация, фильтрация выбросов по IQR, EDA |
| 2 | Data leakage через geo-координаты | Данные | Координаты могут кодировать точный адрес с ценой | Завышенные метрики на тесте | Разделение train/test по географии, анализ feature importance |
| 3 | Drift данных при дообучении | Модель | Искусственный сплит не отражает реальный drift | Демонстрация дообучения неубедительна | Создать drift искусственно (сдвиг цен, новый регион) |
| 4 | Ограничение RAM на Streamlit Cloud (1GB) | Инфраструктура | 11 млн записей не влезут в память | Приложение падает | Семплирование до 1-2 млн, предагрегация, Parquet |
| 5 | Мультиколлинеарность признаков | Модель | Площадь ~ кол-во комнат, регион ~ координаты | Нестабильность линейной модели | VIF-анализ, PCA, выбор одного из коррелирующих |
| 6 | Cold start на бесплатном хостинге | Эксплуатация | Приложение засыпает при неактивности | Долгое первое открытие на защите | "Прогреть" приложение перед защитой |
| 7 | Неравномерность данных по регионам | Данные | Москва/СПб >> остальные регионы | Модель плохо предсказывает для малых регионов | Стратифицированный сплит, отдельный анализ по регионам |

## Data Contract

### Источник: Kaggle Russia Real Estate 2021

**Схема данных:**

| Поле | Тип | Обязательное | Допустимый диапазон | Допустимая доля пропусков | Описание |
|------|-----|-------------|---------------------|--------------------------|----------|
| price | float64 | Да | > 0, < 10^9 | 0% | Цена квартиры в рублях |
| region | int64 | Да | 1-999 | 0% | Код региона РФ |
| object_type | int64 | Да | {0, 2} | 0% | 0=вторичка, 2=новостройка |
| building_type | int64 | Да | {0,1,2,3,4,5,6} | < 5% | Тип здания |
| rooms | int64 | Да | {-1, 0, 1, 2, ...10} | 0% | Кол-во комнат (-1=студия) |
| area | float64 | Да | > 0, < 1000 | < 2% | Площадь в м2 |
| kitchen_area | float64 | Нет | > 0, < area | < 20% | Площадь кухни |
| geo_lat | float64 | Нет | 41.0 - 82.0 | < 10% | Широта |
| geo_lon | float64 | Нет | 19.0 - 180.0 | < 10% | Долгота |
| floor | int64 | Нет | 1 - 100 | < 15% | Этаж |
| level | int64 | Нет | 1 - 100 | < 15% | Этажность дома |

**Требования к актуальности (freshness):**
- Статический датасет, обновления не ожидаются
- Для дообучения: имитация новых данных из held-out сплита

**Периодичность обновления:**
- Однократная загрузка, далее без обновлений
- Дообучение по триггеру (drift detection)
